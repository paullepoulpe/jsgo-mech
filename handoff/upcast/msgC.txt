j2go + runtime: typed sets: Set/LinkedHashSet declarations of Strings, enums and classes without equals are *TSet[X]

Rule "typed collections", third slice: the rule is now a table of kinds (Ctx.collKinds: the
types of the declarations, the classes whose `new` makes one, the stub class with the typed
methods, the view and the types the view serves), with lists and sets in it. A field, local
variable, parameter or result of type Set<X> / HashSet<X> / LinkedHashSet<X> holds a typed set,
*TSet[X] (rt_tset.go), under the conditions of the lists (every value that enters it is
`new LinkedHashSet<>()`, `(n)`, `(collection)`, null or the value of another typed
declaration; every use is one the set or its view serves), and when X is a type whose Go ==
is Java's equals, so that the set finds an element exactly when Java's does (Ctx.goEquals): a
String, an enum, or a class of the program (a handle class too) that inherits equals and
hashCode from Object, as every subclass of it does. A class with its own equals (or with a
subclass that has one), an interface and a library class keep the set erased.

A *TSet[X] holds its elements as X values in insertion order -- the order of the erased
LinkedHashSet, the only set the program makes (no `new HashSet` in the tree) -- and, like the
erased table (htable_), searches a small set linearly and indexes a larger one (a Go map from
element to position); a removed element leaves a dead position until an add compacts the set,
so a cursor or an iterator keeps its place. add, contains and remove of an X (s.has(x),
s.del(x); contains/remove of an Object of another static type go through the view), size,
isEmpty, clear, iterator and the for-each loop work on the X values. Every other site sees
the set as Java's Set through s.asSet(), its one erased view (identity; null is nil; a lookup
of an object of another class finds nothing, as in Java; equals, hashCode and toString as
the erased set computes them; getClass is java.util.LinkedHashSet).

Runtime besides rt_tset.go: foreach_ reads a view by position through one interface for lists
and sets (stepper_, replacing listAt_); Collection_add_s / Collection_remove_s reach a typed
set of Strings without boxing the String (contains_s did already).
Translator: Ctx.typedMethod takes the static types of the arguments (contains/remove are
typed only for an argument that is an X); newTyped names the runtime functions from the kind
(newTList_, newTSet_, tsetFrom_, tsetCopy_).
