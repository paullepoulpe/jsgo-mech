prep(11b-regex-re2): use re2j for every regular expression

The Go translation maps regular expressions straight onto Go's regexp
package (RE2). Production code (java/src outside */testing/) now uses
com.google.re2j, already on the classpath, for every regular expression, so
no JDK-regex-to-RE2 translator is needed later.

Rules:

1. tools/prep/11b_regex_re2.py: `import java.util.regex.X` ->
   `import com.google.re2j.X` (and the one fully qualified use). 24
   production files, plus CompilerOptionsTest and ProcessDefinesTest, which
   pass a Pattern through CompilerOptions.

2. Every String method that takes a regex (34 sites in 21 files: 16 split,
   9 replaceAll, 7 replaceFirst, 2 matches) -> a `private static final
   Pattern X_PATTERN` constant at the top of the class and
   X_PATTERN.split(s) / X_PATTERN.matcher(s).replaceAll(r) / replaceFirst(r).
   The two String.matches(userRegex) calls in Compiler become
   Pattern.matches(regex, s). re2j's split, including the limit argument and
   the dropping of trailing empty strings, and its replacement syntax ($1,
   $0, \\$) were compared with the JDK's and are identical.

3. Constructs that RE2 rejects or reads differently are spelled out so that
   each pattern matches exactly the strings it matched before. The new
   jscomp.base.JavaRegex holds the fragments:
     `.` (no DOTALL)  -> JavaRegex.DOT   [^\n\r\x{85}\x{2028}\x{2029}]
                         (RE2's `.` only excludes \n)              43 uses
     `\s`             -> JavaRegex.SPACE [\s\x0B]  (RE2's \s lacks \x0B)
                         17 uses, and `\s\x0B` inside 3 character classes
     `\S`             -> JavaRegex.NON_SPACE                         1 use
     `$` used by find -> JavaRegex.END  (RE2's `$` does not match before a
                         final line terminator)   2 uses, GoogleCodingConvention
     `\uXXXX`         -> `\x{XXXX}`      PeepholeReplaceKnownMethods
     `[^\p{Alnum}]`   -> `[^a-zA-Z0-9]`  CoverageUtil
   RhinoErrorReporter.replacePlaceHolders relied on the \Q..\E text that the
   JDK's Pattern.quote emits; it now quotes the pieces between the
   placeholders and joins them with DOT*.

4. API that re2j lacks: Matcher.hitEnd/region/regionEnd in JsFileLineParser
   (6 calls). After a successful lookingAt, hitEnd() is `end() == length`
   for this pattern, and region(end + 1, regionEnd) becomes a reset on the
   substring.

Left as they were, on purpose:
  - `$` in the four patterns only used through matches() (same result), and
    in NodeUtil's UNIQUE_NAME_SUFFIX_PATTERN, whose input is a JS identifier.
  - `.` in CompilerOptions.conformanceRemoveRegexFromPath: the pattern text
    is part of CompilerOptions.toString().
  - `\p{L}\p{Nl}\p{Nd}` in JsFileRegexParser: re2j's Unicode tables are
    older than the JDK's.
  - Regular expressions supplied by users (conformance configs, expected
    diagnostics, print-after-each-pass file and chunk filters, the
    instrumentation array name) are now RE2 syntax.
