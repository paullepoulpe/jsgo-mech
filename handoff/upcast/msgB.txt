j2go + runtime: typed lists in parameters and results of methods whose signature is their own; no view where the list is only passed on

Rule "typed collections", second slice (Colls.closedMethod). The parameters and the result of a
method are candidates like fields and locals when the method's signature is its own: a
constructor, a static or a private method, or an instance method of a class that overrides
nothing and that nothing overrides -- with a body, without type parameters, not named by a
method reference (that calls it at the erased signature), not `main`, not a record's or an
anonymous class's constructor; a constructor that an anonymous class calls through `super`
keeps its parameters erased. An argument enters the parameter and a returned expression enters
the result under the conditions of the first slice (a new ArrayList, null, the value of
another typed declaration: now also a call of a method with a typed result); a call is a use
of the result like a read of a variable. A typed list that reaches an erased parameter or
result still goes through its view; one that reaches a typed parameter goes as it is, so
`new Bag(items)` storing its parameter in a typed field makes no view any more.

Translator: Ctx.rtype (the result type of a method, typed or declared) and Ctx.vtype for
parameters, used by the declarations, by groupParams/groupReturn and by the calls of static
methods and constructors. In the program: 472 of 784 List/ArrayList declarations are typed
(137 fields, 214 locals, 68 parameters, 53 results); 15 parameters and 22 results of that
kind belong to groups of overriding methods and are not candidates (too few to add the rule
for groups). Erased, by first reason: exchanges values with an erased declaration 98,
ImmutableList.of 31, Splitter.splitToList 21, used in a lambda 17, Outcome.get 14, assigned a
variable that is not typed 13, nothing enters it 13, Collections.unmodifiableList 7, ...: what
is left is mostly lists that a library makes (the immutable collections).

Runtime (rt_tlist.go, rt_coll.go, rt_object.go, rt_json.go):
- foreach_ reads the view of a typed list by position (listAt_), as it reads an ArrayList's
  slice: an erased for-each loop over a view allocates no iterator;
- TList.iterator() is the list's Iterator without making the view (NullPointerException for a
  null list, as before);
- the view is made once also when two threads ask for it at the same time (atomic.Pointer);
- getClass() of a view is java.util.ArrayList (goName_);
- asList_ lets handwritten runtime code call generated code whatever the translator decided
  (rt_json.go fills SimpleJsonValue.elements(), now a *TList).
