j2go + runtime: a String passed for a CharSequence parameter of a library method is not boxed (variants taking Go strings)

Rule "String for CharSequence" (Conv.strSeq and the table Conv.STR_SEQ, ExprEmitter.call;
runtime variants with the suffix _s in rt_conv.go, rt_base_regex.go, rt_base_text.go;
J2GO_NOSTRSEQ=1 gives the previous translation, J2GO_STRSEQ=1 reports the calls left). Item 5
of the pressure test's ranked list.

CharSequence is any in Go, so a String passed for one was boxed, strobj_(s), and a string in
an interface is an allocation (a literal is not). A call of a library method with a String
for each of its CharSequence parameters now calls a variant that takes Go strings, where the
runtime has one:
    String_contains(name, strobj_(prefix))    ->  String_contains_s(name, prefix)
    PATTERN.matcher(strobj_(line))            ->  PATTERN.matcher_s(line)
    out.append_CharSequence(strobj_(code))    ->  Appendable_append_s(out, code)
The variant does what the method does with the text of the sequence (the functions taking a
sequence now call the variant with csString_ of it, or share the code); the null string is
the NullPointerException that a null sequence gives (csStr_). Appendable.append(CharSequence)
is a method that classes of the program implement too (Output), so
its variant is a function taking the receiver first: a StringBuilder appends the string
(null appends "null", as append(String) does), any other Appendable gets the boxed sequence.
A method of the program that declares a CharSequence keeps the box: it tests the sequence
for null, not for the null string.
