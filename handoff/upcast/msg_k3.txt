j2go + runtime: typed Guava immutables and their builders (ImmutableList<X> is a *TList[X] that never changes; records; keySet of an immutable map)

Rule "typed collections", eleventh slice.

1. Kinds (Ctx.registerTypedColls). A declaration of type ImmutableList<X> / ImmutableSet<X> /
ImmutableMap<K, V> is one of the list, set or map kind and holds the same Go type, *TList[X] /
*TSet[X] / *TMap[K, V], with its `twin` set (rt_timm.go): a typed collection that never
changes (every change is Java's UnsupportedOperationException: the panic value frozen_, which
catch_ makes the exception, so that TList.add and set stay inlinable). A List<X> that holds an
ArrayList on one path and ImmutableList.of() on another is therefore one typed list.
- Erased code sees an immutable typed collection as its twin, the runtime's ImmutableList /
  ImmutableSet / ImmutableMap with the same elements, boxed, made the first time erased code
  needs it: asImm(), which asList() / asSet() / asMap() return for an immutable collection (a
  place of type ImmutableList / ImmutableCollection and a method that javac finds in those
  classes -- reverse(), asList(), subList -- get the twin directly).
- An expression of the static type ImmutableList<X> enters a typed declaration whatever made
  its value (Colls.inflow, immutable()): from an erased source Ctx.coerce emits tlistImm_(tc, x)
  / tsetImm_ / tmapImm_, the typed collection of that erased object, made once and remembered
  by it (ImmutableCollection.typed_). A Java object is one typed object and one erased object,
  each found from the other, so == and "copyOf of an immutable collection is the collection"
  hold on both sides; the contents never change, so the two cannot be told apart. Such an
  expression erases nothing and nothing erases it.
- Where the typed declaration is the target, ImmutableList.of(a, b) is the typed factory
  (immutableListOf_[X](tc, a, b), immutableSetOf_, immutableMapOf1_..5_ with the arguments in
  Java's order; t<kind>EmptyImm_ for of(): one empty collection per element type, its twin the
  runtime's one empty collection), ImmutableList.copyOf(c) is immutableListCopyOfT_ of a typed
  collection of the same type (an immutable one is itself), ...CopyOfArr_ of an array, or
  ...CopyOf_ of an erased collection, and keySet() of an immutable typed map is its typed key
  set (TMap.keySetImm: one object, the twin of the erased map's key set).
- Builders: ImmutableList.Builder<X> / ImmutableSet.Builder<X> / ImmutableMap.Builder<K, V>
  declarations are kinds of their own (*TListBuilder[X], *TSetBuilder[X], *TMapBuilder[K, V]:
  the elements as they are, build() the typed immutable collection), typed when every value
  that enters is a new builder (builder(), builderWithExpectedSize(n), new Builder<>()) or
  that of another typed builder, and every use is add / addAll / put / putAll (whose result is
  the builder again: Colls.use follows the chain), a build, or a typed builder declaration. A
  builder has no erased view.
- Records: a component is one declaration -- its field, the parameter of the canonical
  constructor and the accessor javac makes (Colls.recordComponent) -- and can be typed like any
  field; methods of records can be closed methods. (Record components were erased "a record
  component": with the immutables they would have been 43 crossings.)
J2GO_COLLS_NOIMM=1 and J2GO_COLLS_NOBUILDERS=1 are the rules without them.

erased ImmutableMap reports a key given twice as Guava does ("Multiple entries with same key:
