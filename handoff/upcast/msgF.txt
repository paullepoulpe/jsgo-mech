j2go + runtime: typed collections of boxed primitives, of Object and of erased library types (List<Integer>, Map<String, Integer>, Set<Character>, List<List<String>>)

Rule "typed collections", sixth slice: the types a typed collection holds (Ctx.typedArg, one
function for every kind and type argument; it replaces typedElem's "one Go type and no type
arguments"). Besides a String, a class, an interface or a handle without type arguments:
- a boxed primitive (Integer, Long, Character, Boolean...) or Object, held as the box it is in
  erased code: List<Integer> is a *TList[any], Map<String, Integer> a *TMap[string, any]. The
  elements gain nothing by themselves (they were boxes and stay boxes), but the collection is
  a typed declaration: its other type argument is unboxed, its loops read it in place, and it
  no longer keeps the declarations it exchanges values with erased;
- a library type with type arguments, held at its erasure, for the elements of lists and
  deques as the previous commit did for the values of maps: List<List<String>> is a
  *TList[List]. A generic class of the program stays excluded (it may be a Go generic type).
The elements of a set and the keys of a map are compared, so for them the type must be one
whose Go == is Java's equals: as before a String, an enum or a class of the program without
equals of its own, and now a boxed primitive that is not a floating-point number (two boxes
of equal values of one type are == as Go interfaces, and boxes of different types are not, as
Integer.equals(Long) is false; the erased table compares them the same way). Float and Double
stay out: 0.0 and -0.0 are different keys and NaN equals NaN in Java, not in Go. Object stays
out as a compared type.
contains / remove / get / containsKey with a primitive argument of the element's type are
typed too (Ctx.isElement: `chars.contains('h')` is `chars.has(any(uint16('h')))`). The
conversion of a type that is `any` in Go is named after the Java type (tc_Integer, tc_Object).
