j2go + runtime: typed collections, first slice: List/ArrayList fields and locals that hold only lists made for them are *TList[X]

Rule "typed collections" (Colls; Ctx.coerce; rt_tlist.go). The decision is made declaration by
declaration, as GenScan decides type parameter by type parameter. A field or a local variable
of type List<X> / ArrayList<X> holds a typed list, *TList[X] (a slice of X values, not of
boxes), when
- X has one Go type and no type arguments (a String, a class, an interface, a handle);
- every value that enters it is `new ArrayList<>()`, `new ArrayList<>(n)`,
  `new ArrayList<>(collection)`, null, or the value of another typed declaration of the same
  element type, so that it never holds a list that erased code made; and
- every use is one the typed list or its erased view serves as the ArrayList did: a List
  method (not subList, listIterator, getClass), a for-each loop, ==, a string concatenation,
  or a place of type List, Collection, Iterable, Object or a type variable. A place of the
  class type ArrayList must be a typed declaration too, or the list stays erased.
Not typed: the variable of a for-each loop, a record component, a field of a handle class, an
annotated field (args4j reads those).

get, set, add, add(int, x), remove(int), size, isEmpty, clear and the for-each loop
(`it := l.each()`) work on the X values. Every other site (a wildcard or raw type, Object, a
parameter, a result, a library call, any other List method) sees the list as Java's List
through l.asList(): the list's one erased view, made on first use, which boxes and casts with
the conversions the erased code makes for X (tc_string, tc_p_JSType..., generated per element
type in g_0casts.go from Ctx.coerce). Java's behaviour is kept:
- one object: the view is the list's identity for erased code (==, changes made on either
  side are the same list's);
- null is nil on both sides (a nil *TList has the nil List as its view), and a call or a loop
  on a null list throws NullPointerException where the erased code did;
- the view implements List as ArrayList in rt_coll.go does (messages of
  IndexOutOfBoundsException, equals/hashCode/toString, iterator with remove); a String is
  looked up in it without boxing each element (contains_s).
Nothing converts an erased list into a typed one: no conversion from the erased form exists
(Ctx.coerce throws, so a hole in the analysis stops the translation instead of compiling).
Accepted difference: an element of the wrong type that unchecked code puts into a typed list
through its view fails there with the ClassCastException that Java throws at the first typed
read (or never, if it is never read at its type).

In the translator a typed declaration, and every expression that reads it, has the type
TList<X> of a stub class compiled with the program (Ctx.TLIST_STUB: the typed methods), so
the existing machinery of typed declarations types the calls, and Ctx.coerce is the one place
that turns it into any other type (through the view). J2GO_COLLS=1 reports the counts and the
reasons declarations stay erased, J2GO_COLLS=2 each declaration; J2GO_ERASED=1 skips the rule.
