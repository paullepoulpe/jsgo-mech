j2go + runtime: typed maps: Map/LinkedHashMap declarations are *TMap[K, V]; loops over their keys, values and entries read the map itself

Rule "typed collections", fifth slice: a kind with two type arguments (Colls.Slot.args,
Ctx.typedArgs; a conversion per argument). A field, local variable, parameter or result of
type Map<K, V> / HashMap<K, V> / LinkedHashMap<K, V> holds a typed map, *TMap[K, V]
(rt_tmap.go), under the conditions of the other kinds: every value that enters it is
`new LinkedHashMap<>()`, `(n)`, `(map)` (the only hash map the program makes: no
`new HashMap` in the tree), null or the value of another typed declaration of the same K and
V, and every use is one the map or its view serves. K is a type whose Go == is Java's equals,
as for a set (a String, an enum, a class of the program without equals of its own:
Ctx.goEquals). V is a type with one Go type; it may be a library type with type arguments
(Ctx.typedValue): Map<String, List<Node>> is a *TMap[string, List], whose values are the
erased List that such a value is everywhere else (a typed list that is put into the map goes
in as its view, the one object).

A *TMap[K, V] holds its keys and values as K and V values in insertion order (the erased
LinkedHashMap's order) and, like the typed set, searches a small map linearly and indexes a
larger one (a Go map from key to position); a removed mapping leaves a dead position until a
put compacts the map, so a cursor or an iterator keeps its place. get, put, containsKey
(m.has(k)), remove (m.del(k)), getOrDefault (m.getOr(k, v)), putIfAbsent and computeIfAbsent
with a key that is a K by its static type, size, isEmpty and clear work on the K and V values;
a missing key gives Java's null (the null String for a String). A for-each loop over
m.keySet(), m.values() or m.entrySet() of a typed map reads the map itself, without the view:
`it := m.eachKey()`, `m.eachValue()`, `m.eachEntry()`. The variable of the loop over the
entries is a *TEntry[K, V] (a fifth kind, "entry": its candidates are the variables of loops
over the entrySet() of a map candidate, typed when the map is): getKey, getValue and setValue
on the K and V values, an object per iteration as in Java (it reads and writes the map's
value while the mapping exists and keeps the last value after its removal, as the erased
entry does); an entry that goes anywhere else goes as a Map.Entry through e.asEntry().
Every other site sees the map as Java's Map through m.asMap(), its one erased view: identity;
null is nil; a lookup with an object of another class finds nothing, as in Java; keySet(),
values() and entrySet() are parts of the view (no allocation, as for the erased map), with
iterators that remove; equals, hashCode and toString as the erased map computes them; getClass
is java.util.LinkedHashMap.
