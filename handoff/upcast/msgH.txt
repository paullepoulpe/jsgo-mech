j2go + runtime: typed collections of type variables and of generic classes of the program; the erased view is part of the collection (no object per view)

Rule "typed collections", eighth slice.

1. Type arguments (Ctx.typedArg). A typed collection now also holds
- a generic class of the program, at the Go type it has: List<LinkedDiGraphEdge<N, E>> in
  LinkedDirectedGraph<N, E> is a *TList[*LinkedDirectedGraph_LinkedDiGraphEdge[N, E]],
  Deque<HamtPMap<K, V>> a *TDeque[*HamtPMap[K, V]] (not with a wildcard type argument). As
  the element of a set or the key of a map too (a pointer or an interface is comparable; by ==
  or by equals as for any class);
- a type variable: the Go type parameter where the variable is one (List<T> in a generic
  class that is a Go generic type is a *TList[T]), else what it is erased to (its bound). Not
  as a compared type where it is a Go type parameter: the parameter's constraint is `any`, and
  TSet / TMap need `comparable` (and Object, which an erased type variable usually is, stays
  out as a compared type as before).
A declaration whose type arguments name a Go type parameter has that type only inside the
generic declaration: `items` is a List<T> there, but `c.items` of a Stack<String>, or `items`
in a subclass Words extends Stack<String>, is a List<String>. Such a declaration is typed
only if every expression that reads it has the declaration's own type arguments (Slot.open:
"read at another instantiation of its type variables" keeps it erased).
Conversions: an element type that is a type parameter has the conversions of a value of a
type parameter (tcT_[T](): boxT_, unboxT_; rt_tlist.go); an instantiation that names type
parameters has a generated generic function with the conversions the erased code makes for
the class (tc_p_LinkedDirectedGraph_LinkedDiGraphEdge_N__E_[N, E](), g_0casts.go: self() of a
pointer that is not nil). Both are one object per instantiation (single_).

2. Flow (Colls).
- The result of a lambda is a place of the type that the method of the lambda's interface
  returns for it (a Supplier<List<X>> returns a List: the view); it kept the list erased
  ("used in LAMBDA_EXPRESSION", "returned from a lambda").
- Collections.unmodifiableList(x) / unmodifiableSet / unmodifiableMap is x in the runtime
  (rt_coll.go returns its argument), so what enters a declaration through it is x, and the
  typed code is x.
- A declaration that no collection enters -- only null does: a parameter of a method that the
  program never calls or calls with null, a field that is never assigned -- is typed like any
  other, and no longer keeps the declarations it is assigned to erased
  (J2GO_COLLS_NOUNMADE=1: the previous rule). J2GO_COLLS_NOGENERIC=1 is the previous rule for
  the type arguments.

3. Runtime: the erased view of a typed list, set, deque or map is a field of the collection
(TList.view, set when the collection is made), not an object made on first use. The first
version of this slice made the edge lists of the graph nodes typed lists, which erased code
reads (getInEdges() / getOutEdges() are methods of a group of overriding methods): each list
then allocated a view, 4.2M objects more on bundle (189.68M -> 194.09M; +0.6% cpu). With the
view in the collection a typed collection that erased code sees is one object, as the Java
collection is: asList() is &l.view, without an atomic load. A TList, TSet and TMap have the
size they had (the field replaces the pointer to the view; the map's keySet(), values() and
entrySet() views are the map's view converted to their types); a TDeque is 8 bytes larger.
