# Trial re-flip (branch reflip-trial)

What happens when the post-flip half (postflip5: 233 commits that change `go/`, steps.txt) is
replayed on a new translator output: main-r8-typed (typed generics, typed collections) merged
with main-r8-nodestore (the node store the collector never scans).

    flip          dd6a910b  run.sh's raw output frozen (813 g_*.go)
    flip (prep)   40caeeed  gofmt; reflip/rename.sh (below)
    replay        tools/postflip/replay-all.sh -base 40caeeed -noverify -trim \
                    -steps tools/postflip/reflip/steps.txt -overlay tools/postflip/reflip/patches \
                    -toolfix tools/postflip/reflip/toolfix.sh -check '<tc> go/closure'
                  (<tc>: go build -o tc ./reflip/tc in tools/postflip; a type check after every commit)

The replay runs to the end. A second run from 40caeeed with the final files gives the same
tree (go/closure 4c78626f), and that tree passes tools/prune/verify.sh (runtime tests ok,
checks/bundle/downlevel/advanced MATCH; the j2go selftest is a pre-flip gate and does not
build after rename.sh).

Files here: `steps.txt` (the edited copy of ../steps.txt: `#= <commit> <status>: <reason>`,
dropped lines commented `#- `), `patches/` (10 regenerated patches, used instead of the patch
of the same name), `toolfix.sh` (6 fixes applied to the tools of every step's commit),
`rename.sh` + `rename-names.txt`, `tc/`, `table.py` (prints the table: `python3
tools/postflip/reflip/table.py`).

## What had to be done, in the order met

1. **Two runtime families with the same names.** Typed j2go writes typed collections against
   rt_tlist.go/rt_tmap.go/rt_tset.go/rt_tdeque.go, TList/TMap/TSet, tconv_ and tc_* conversions,
   null_/isnull_/unboxT_: code derived from the post-flip runtime of step 3 that then went its
   own way. The post-flip patches (003 onward) create the same files and names with other code.
   The trial keeps both: rename.sh gives j2go's 183 colliding top-level names a j/J prefix
   (JTList, jtconv_, jtc_*). The price: the post-flip tools do not know JTList/JTMap/JTSet, so
   they neither turn them into slices and Go maps (native) nor give them Go method names
   (tnames), and the tree ends with two typed collection families.
2. **Tools written for a package with no generic types of its own** (toolfix.sh 1-4): uses of a
   generic type's fields are other objects than the declaration (the tools saw no uses and
   rewrote the declaration alone); no boxing spelling for a type with type parameters; a method
   of a generic type called at an instantiation has a signature no declaration has (colls and
   native typed `SimpleBiMap[K, V].inverse()` as `map[string]string`). Fixed conservatively:
   such slots stay as they are.
3. **Tools that match the erased lambda wrapper `&F_fn{func...}`**: j2go writes typed adapters
   (`&Consumer_tfn_Node{...}`). funcparams needed parentheses for a method value of one
   (toolfix 5); passfn (911d9169), all or nothing, finds 188 uses that do not fit: dropped.
4. **A hole in colls that the first flip's text never reached** (toolfix 6): the variable of a
   short declaration `x := conv(el)`.
5. **Steps j2go now does**: Optional as a value (fafc63f9: dropped; df574d16's generics run
   rewrites nothing and its runtime patch is reduced to the helpers later tools write), PMap and
   HamtPMap generic (7992da4a), the PGO profile removal.
6. **Manual patches** (51): 11 apply as they are, 5 partly (3-way merge; the files whose text
   differs are left out, the rest type-checks), 35 are dropped, 4 of them in commits whose
   runtime patch still applies. They edit hot generated code by hand (LinkedDirectedGraph, DataFlowAnalysis,
   ControlFlowAnalysis, NodeTraversal, RemoveUnusedCode, Node, ...), exactly where typed j2go
   writes other text. Dropping the executor/thread patches (25c89a69) takes the runtime patch
   07885c84 and the manual patches 9bdc7957 and 08dc9ce1 with it.
7. **Runtime patches** (79): 75 apply as they are; 3 regenerated by 3-way merge next to j2go's
   typed-view cases in rt_coll.go and for Optional; 1 dropped (07885c84). One runtime test
   patch added (rt_io_test.go; rt_idmap_test.go dropped: it tests against the erased
   LinkedIdentityHashMap).

## What a real re-flip needs

- One typed collection runtime: j2go must write against the post-flip tip's family (or the
  post-flip colls/native/tnames/imm steps must be re-based on j2go's). Then steps 1-5 and most
  later colls runs become no-ops and native/tnames reach j2go's lists; rename.sh goes away.
- The tool fixes of toolfix.sh as real tool commits, with the generic cases handled instead of
  left (collections in generic classes, values exchanged with instantiated methods).
- passfn, funcparams, lambdas taught the typed adapters `X_tfn_Y` (or j2go writing F_fn where
  the tools then unwrap).
- The 35 dropped manual patches re-made on the new text (or turned into tools, or made
  unnecessary by j2go: several target what typed j2go already changed).
- The gofmt of the flip commit (regen.sh does it; run.sh alone does not).
