# Library generics in the translator: how it works today, what stands in the way, what to do

Study only. Nothing was changed on `main`, in `agQ` or in `agQr`. The measurements were made in
a worktree of `main` at a5b5eaf9 (`/mnt/data/ubuntu/jm/wt/agU`, branch `inb-libgen-study`; two
uncommitted study files there: `tools/j2go/src/j2go/LibGenScan.java` and a 6-line hook in
`Main.java`). No benchmark, no gate and no post-flip tool was run.

All paths below are under
`/mnt/data/tmp/claude-1000/-home-ubuntu-work/9db246f3-01a3-48c8-9bf5-1c94d1ed78d6/scratchpad/libgen/`
unless absolute.

## 0. The answer

1. **The Java source is far cleaner than the rule's "known cost" assumed.** javac with
   `-Xlint:rawtypes,unchecked` over the 809 translated files reports 0 warnings; there is no
   `@SuppressWarnings("rawtypes")`, and 32 `@SuppressWarnings("unchecked")` in 19 files, of which
   2 casts involve a library generic type. So there are **no raw library types at all**. The
   accounting's "carrier raw" casts (240) are therefore all type arguments lost on the way in Go,
   not raw Java declarations; its assumption holds.
2. **Variance is rare.** Of 9,507 flows of a value into a place of a library generic type, 8,207
   have exactly the target's type arguments, 1,139 meet a wildcard whose bound is exactly the
   source's argument (no conversion needed once the place is typed at the bound), and **161 need
   something**: 43 covariant (`List<Sub>` into `? extends Super`), 9 contravariant, 109 into an
   unbounded `?`. On the declaring side, 21 overriding methods narrow the element type of a
   wildcard result, in two families (the graph classes 15, the scope classes 6).
3. **Functional interfaces are the largest and easiest part.** 1,004 of the 1,360 flows into a
   functional-interface place are a lambda or a method reference, which takes whatever type the
   place has. No functional value is compared by identity, tested with `instanceof`, used as a
   map key or set element, or passed as an `Object`. About 1,040 of the accounting's 2,020 sites
   are this stage.
4. **The erased interfaces are generated by the translator** (`g_zstubs.go`, from the methods the
   program calls), not handwritten. Typing them is a change in `Stubs.generate` plus the runtime
   types that implement them.
5. Recommendation: stage F (functional interfaces as named generic func types) first, then
   iteration and collections together as one typed-interface stage, keeping today's erased view
   only for `?` places. Do not do option C (unified family with erased interfaces) as a stage of
   its own: it removes 0 of the 2,020 sites and costs a tool re-adaptation.

## 1. How it works today

### 1.1 Translator (repo `/home/ubuntu/work/jsgo-mech`, `tools/j2go/src/j2go/`)

| mechanism | where | what it does |
|---|---|---|
| erasure as the default | `Ctx.erase` (1504), `Ctx.goType` (1568) | a library `DeclaredType` is its erasure; `kind()` is `IFACE`/`CLS`; a type variable that is not kept is `any` |
| the `XOf[...]` aliases | `Ctx.declType` (1592), `Ctx.typeArg` (1609), written by `Main` (343-347) to `g_0aliases.go` | only in declarations (`goSig(.., decl=true)`): a parameterized library type is spelled `NameOf[args]` with `type NameOf[T0 any] = Name`. A wildcard is its `extends` bound or `any`; an erased type variable is `any`; a box is `BoxedOf[prim]`. 52 aliases in today's output (`out/g_0aliases.go`), 1,419 uses (`baseline.out`) |
| the erased interfaces themselves | `Stubs.generate` (78-99) into `g_zstubs.go` | `type Iterator interface { hasNext() bool; next() any }`, `type List interface {...}`: one Go interface per library interface, with the methods the program calls (`Ctx.extMethods`, filled by `noteMethodOn`). 125 interfaces. Runtime types (`rt_*.go`) implement them |
| typed collections | `Colls` (whole file; `candidates` 362, `flows` 417, `decide` 949), `Ctx.registerTypedColls` (425), `Ctx.typedArg` (564), `Ctx.STUBS` (258) | a declaration becomes `*TList[X]` / `*TSet[X]` / `*TDeque[X]` / `*TMap[K,V]` / a typed builder when (a) each type argument is one a typed collection holds, (b) every value entering it is a new collection of its kind, null or another typed declaration, (c) every use is a method of the stub class or a place of a view type. Decided per declaration; a group of overriding methods is one declaration. Inside the translator the declaration has the stub type `j2go.rt.TList<X>` (`cx.refinedVars`, `cx.typedResults`, `cx.refinedTrees`) |
| the erased view | `Ctx.coerce` (1701-1717) | a typed collection meets any other type through `.asList()` / `.asSet()` / `.asMap()` / `.asDeque()` / `.asImm()` / `.asSorted()` / `.asEntry()`; an erased `ImmutableList` enters a typed declaration through `tlistImm_(tc, x)`. 1,198 view calls in today's output |
| element conversions | `Ctx.tconv` (815), `Ctx.tconvsOf` (792), emitted by `Main` (357) into `g_0casts.go` | one `tc_X` / `tce_X` descriptor per element type (`box`, `unbox`, `null`, `byEquals`); passed to every typed constructor. 330 descriptors, 2,249 uses pre-flip |
| casts and boxes at erased results | `Ctx.coerce` (1730-1820), called from `ExprEmitter.call` wherever javac's instantiated type and the erased declaration differ | `cast_[*C]`, `to_C`, `icast_I` (one function per interface, `Ctx.icasts`), `str_`, `Node_of_`, `unbox_[T]`; the other way `obj_`, `strobj_`, `x.box_()`, `any(x)` |
| for-each | `StmtEmitter` (483-494) | `it := foreach_(c)`; `it.v` is `any` and is coerced to the loop variable's type; over a typed collection `it := list.each()` with a typed `it.v` |
| lambdas, method references | `ExprEmitter.lambda` (1773), `typedAdapter` (1718), `adapterName` (1697) | the func literal is wrapped in the adapter struct of the target interface: `&I_fn{func(x any) R}`; for a library interface, when a parameter or result is "assertable" (`Ctx.assertable` 2724: String, handle, leaf class, interface, array), the typed adapter `&I_tfn_A_B{func(a A) B}` whose method converts at the erased signature |
| adapter types | `Stubs.generate` (176-260) | three loops: `I_fn` (erased func), concrete `I_tfn_A_B` per instantiation (`cx.extConcreteAdapters`), generic `I_tfn[P0, R]` for type variables. 200 adapter types in today's `g_zstubs.go` |
| classes implementing a library generic interface | `Ctx.analyzeMethods` (2157), `Emitter.bridges` (860), `Emitter.extBridges` (945) | the method group has the root's erased signature (`compare(a_ any, b_ any)`), the body casts on entry |
| library methods | `ExprEmitter.call`; `Stubs.generate` (158-174, 261) | instance method stays a method on the Go type of the same name; static becomes `Owner_name`; default methods are receiver-first functions (`Iterable_forEach`, `Ctx.defaultBridgeBody` 2748). All with erased signatures unless the runtime declares the function generic (`Conv.loadGenerics` 381: 116 generic runtime functions today) |
| what is already typed | `Ctx.registerValueLibs` (230): `java.util.Optional[T]` is a generic value; `GenScan`: the program's own generic classes, interfaces and static/private generic methods; `GenScan.refine` (127): a local of one of the program's generic types with wildcard type arguments that is never reassigned takes the type of its initializer (not for library types: `tryRefine` 413); `Ctx.covariant` (1888): a class-typed covariant override is a method group of its own with a bridge | |

So the erasure is produced in exactly four places: `goType` for a library `DeclaredType`,
`Stubs.generate` for the interface declarations, `lambda`/`typedAdapter` for function values,
and `coerce` for everything that crosses.

## 3. Design options

Common to all: a place's Go type comes from javac's type arguments by the mapping `declType`
already uses for the aliases (wildcard to its bound, `? super X` to X, `?` and an erased type
variable to `any`, a box to `any`, a kept type variable to the Go type parameter). A flow
converts as follows; the counts are section 2.2's.

| flow | conversion |
|---|---|
| exact, or wildcard with the same bound (9,346) | none |
| lambda or method reference (1,004 of the functional flows, whatever the variance) | the func literal is written at the target's types |
| contravariant function value (1 real) | a closure `func(x Sub) R { return f(up(x)) }` |
| covariant (43) and narrowing overrides (21 methods) | choice per stage, in order of cost: (1) the place stays erased as today; (2) a read-only covariant view made at the flow (one small object, identity not kept; valid because Java allows no write through `? extends` and the uses are read-only, section 2.3); (3) the callee becomes a Go generic function in the element type where it is static or private and not in an override group |
| into `?` (109) | the collection's erased view, as today, under a second, non-generic interface that every typed collection keeps (`anyColl()`); the runtime functions that take `Iterable<?>` keep their erased parameter |
| from `Object` (2 unchecked casts, 5 `instanceof`) | assertion to the non-generic marker interface; the 2 casts stay erased at that declaration |

`proto/p.go` is a 150-line Go program with these shapes (named generic func types with methods,
`Iterator[T]` / `Iterable[T]` / `Collection[T]` / `List[T]` implemented by a typed list itself,
the nil-keeping `asList()`, the `?` view, a covariant view, a class's method value as a
predicate, `comparingInt`); it passes `go vet` and runs (go 1.27.3, module `go 1.24`).

### Option A: typed interfaces for all library generics at once

- Emits: `type Iterator[T any] interface { hasNext() bool; next() T }`, `Iterable[T]`,
  `Collection[T]`, `List[T]`, `Set[T]`, `Map[K, V]`, `Map_Entry[K, V]`, `Deque[T]`, ...
  (generated by `Stubs.generate` with the receiver's type parameters), functional interfaces as
  in F below, every `XOf[...]` alias gone. `new ArrayList<X>()` is always `newTList_[X]`: no
  proof is needed to type a collection, because every place it can reach is typed or is
  `Object`. `Colls` shrinks to the choice between the concrete pointer `*TList[X]` and the
  interface `List[X]`.
- Runtime: the erased collection library is rewritten generic or deleted (about 5,100 lines in
  `rt_coll.go`, `rt_coll2.go`, `rt_guava*.go`; 475 of their 676 functions have `any` or an erased
  collection in the signature), the typed half gets the interface methods, `tconv_` descriptors
  are needed only for the `?` view and for `byEquals`. `tools/protogen` must emit typed repeated
  fields (`rt_proto_gen.go`, 15,815 generated lines, returns `List`). 121 static generic library
  methods and 269 instance methods in use.
- Post-flip: about 60 of the 274 active steps lose their subject (every row of the table in 1.3
  except "typed collections to slices and Go maps", `etaconv` and part of the cast folding), and
  nearly every remaining tool reads different text (`.asList()`, `tc_X`, `foreach_`, `cast_[`).
- Sites: all of F, I, C, K, O: about 1,925 of 2,020, plus R2's 334.
- Risk: high. One change touches the four places of 1.1, 8,000 lines of runtime and the
  generator, and cannot be bisected with the `J2GO_NO<RULE>` switches the project uses.
- Size: translator about 1,500 changed lines in `Ctx`, `Colls`, `ExprEmitter`, `StmtEmitter`,
  `Emitter`, `Stubs`, `Conv` (my estimate from the functions listed in 1.1); runtime as above.

### Option B: staged

**B1, functional interfaces (F, with Comparable K).**

- Emits: one named generic func type per library functional interface, with the interface's
  methods declared on it, so that call sites and default methods keep their form:
  `type Supplier[T any] func() T` with `func (f Supplier[T]) get() T { return f() }`;
  `Function[T, R]`, `Predicate[T]`, `Consumer[T]`, `BiFunction`, `BiConsumer`, `BiPredicate`,
  `Comparator[T] func(a, b T) int32`, `ToIntFunction[T]`, `Callable[T]`, `Runnable`. Guava's
  `Predicate` / `Function` / `Supplier` are aliases of the java ones (Guava's `Predicate` has
  both `apply` and `test`; 5 flows pass one as the other). A lambda is the func literal at the
  place's types; a method reference likewise; an object of a class implementing the interface
  (43 flows, 20 classes) is its method value `Predicate[Node](x.apply)`; the class's method has
  its typed signature and no bridge. `Comparable<T>` is `interface { compareTo(T) int32 }` for
  the 11 classes.
- Erased collections, until B2: a function given to a method of an erased collection
  (`computeIfAbsent` 57, `forEach` 16, `List.sort` 12, `ImmutableMap.Builder.put` 15, ...) goes
  through a generic runtime function that boxes at the collection, as post-flip step 486's
  `rt_tfnapi.go` does (`mapComputeIfAbsentT_`). On typed collections it is a typed method.
- Runtime: the 51 library methods that take a functional value, the `Comparator` statics and
  defaults (receiver-first generic functions, since a Go method has no type parameters of its
  own), `Predicates_*`, `Suppliers_memoize`, and the typed Optional's `filter(p Predicate)` and
  `ifPresent(c Consumer)`, which take the erased interface today (`rt_base.go:644, 655`; 102
  `filter` sites) and become `Predicate[T]` / `Consumer[T]`; about 52 runtime functions name a functional interface today (`rt_coll.go` 22,
  `rt_guava*.go` 17, `rt_base.go` 7, `rt_coll2.go` 6).
- Variance: lambdas need none; 1 real contravariant flow gets a closure; the 36 flows into
  erased program type variables (`runInCompilerThread(Callable<T>)`) are typed `Callable[any]`
  and keep one box each.
- Translator: `Ctx.goType` / `declType` / `typeArg` (a registry of functional interfaces),
  `Ctx.coerce` (function to function, class to function, function to `Object`),
  `ExprEmitter.lambda`, `typedAdapter`, `adapterName` and the method-reference path,
  `Stubs.generate` (the three adapter loops become the func type declarations),
  `Emitter.bridges` / `extBridges`, `Conv.upcast` (must not treat a func type as an interface),
  `Colls.lambdaResult`. About 500-700 changed lines in 5 files; runtime about 500 lines plus
  tests. Both numbers are estimates.
- Post-flip: `lambdas` (69), `funcparams` for library interfaces (76, 136, 173, 255, 277, 285),
  `fnobj` (279), `adapters` (417, 425), `tfnargs` (434, 437), `lamparams` (457), `implsplit`
  (467, 468), `tfnparams` (469, 471), `fntypes` (482), `tfnapi` (486), `deadtfn` (477, 486),
  `tcmp` (472, 481, 486) and runtime patches 252, 276, 284, 433, 470 lose their subject: 22
  step entries, 12 tools. `funcparams` and `fnobj` stay for the program's own functional
  interfaces (61 lambdas: `CompilerPass`, `NodeUtil.Visitor`, ...) and must read func literals
  without a wrapper; `etaconv` (461) stays and sees more literals.
- Sites: about 1,040 + 45. Risk: low to medium; the proof obligations (no identity, no
  `instanceof`, no `Object` flow) are measured at zero, and should be checked by the translator
  as refusals (as it refuses `==` between two Optionals).

**B2, iteration (I).** `Iterator[T]`, `Iterable[T]` as generic interfaces; `TList.iterator()`
and the other typed collections return `Iterator[T]`; the 16 program classes implementing them
get typed methods; `foreach_` over an `Iterable[T]` has a typed cursor. Flows into an
`Iterable`/`Iterator` place by source (606): results of library calls 218, of program calls 144,

`String.join`), the 6 scope methods, 44 flows into `Iterable<?>`. Post-flip: `iters`, `tviews`,
`tgeneric`, part of `ranges`. Translator about 200 lines, runtime about 300 (estimates).

**B3, collections (C).** As option A's collection part, after B1 and B2.

### Option C: keep erased interfaces, emit the unified typed family from the translator

- Emits what step 402 produces: the post-flip `TList`/`TMap`/`TSet` (one family, `Has` / `GetOr`
  / `Delete`, `tch_` conversions, `ImmutableList_Builder`, "a typed collection is its own
  erased view" of 554b and 556) directly, with the post-flip runtime moved to `main`.
- Removes: the flip's rename to `JT*`, step 402 and its runtime patch; steps 3-5, 87-90, 322,
  336, 338 collapse into one run of `colls/run.sh` (what 403 is today).
- Sites removed: 0 of the 2,020. It is purely structural.
- Cost: every step between 5 and 402 that reads collection text (`native` 60-63, 91, 92,
  `ranges`, `iters`, `strkeys`, `immbuild`, `tnames` 324, `immnames` 326, `castfold`, ...) runs
  on input it has never seen; that is a tool re-adaptation of the kind `toolfix.sh` records (27
  fixes, 885 lines over four flips). And it would be redone by B3, which changes the same text
  again.

## 4. Recommendation

Order: **B1 (functional + Comparable), then B2 and B3 together as one "typed collection
interfaces" stage, done kind by kind behind switches (Iterator/Iterable, List/Collection, Set,
Map/Entry), with the `?` view kept. Not C.** Reasons: B1 is half of the sites, has no variance
problem and no dependency on the collection runtime; B2 alone leaves an erased-to-typed
boundary inside the collection hierarchy (26 + library results), which B3 removes, so doing
them together avoids writing conversions that are deleted one stage later; the family
unification that C wants falls out of B3, where the translator's typed family becomes the only
one.

For variance in every stage, start with choice (1) (the place stays erased, as today) for the
43 + 21 covariant cases, so that each stage only removes conversions; then measure the covariant
view on the graph family as a step of its own.

### 4.2 Gating and measuring each stage

- Each stage is a translator rule with its own switch (`J2GO_NOFNTYPES=1`, then
  `J2GO_NOLIBGEN=iter,list,set,map`), like the rules in `Conv`, so a failing gate can be
  bisected and the previous translation is one environment variable away.
- Refusals instead of assumptions: the translator stops with a message on a functional value
  compared with `==` (other than with null), tested with `instanceof`, cast, or passed as an
  `Object`; on an unchecked cast to a typed library interface outside a list of the 2 known
  ones. Today's count of each is 0 (section 2.3), so the refusals cost nothing and keep the
  proof obligation checked on every run.
- Gate: the pre-flip gate of `main` (`/mnt/data/ubuntu/jm/gate.sh`: `tools/prune/verify.sh`,
  runtime tests, the j2go selftest, the four end-to-end comparisons checks / bundle / downlevel /
  advanced MATCH). The translator runs in 10 s, so the emit-and-`go build` loop is short.
- Measure, per stage: `baseline.sh <output dir>` before and after (today: 1,112 adapter
  literals, 200 adapter types, 984 + 370 casts, 1,198 views, 330 descriptors, 52 aliases); the
  18% benchmark subset in alternating rounds against the previous binary, as REFLIP4.md does;
  allocation count, since B1 removes one adapter object per capturing lambda and a box per
  erased result. I expect B1 to show mostly in allocation and little in time: 188 of its
  adapters are `PassFactory` lambdas run once per pass.
- The fifth flip after B1: drop the 22 step entries listed in option B1 from the step list,
  replay, and compare the census with the fourth flip's. The stage is worth it when the replayed
  tree has the adapter and bridge rows near zero with fewer steps; the measure of success is
  sites removed and steps removed, with time as a no-regression gate.

## 5. What I could not determine

- **No time or allocation number.** Nothing was built or run. Whether the covariant view or
  today's per-element cast is faster on the graph classes, and what B1 saves, are unmeasured.
- **Step impact is read, not run.** The lists of post-flip steps that "lose their subject" come
  from the step descriptions in `steps.txt`; no tool was run on output of the proposed form, so
  the number of tool fixes a fifth flip needs is unknown. The translator's change sizes are
  estimates from reading the functions involved.
- **The site-to-category link is by method name** (section 2.4): 251 of 1,986 sites not linked,
  and a linked site gets the worst category of its method. The boxing (524) and `any`-parameter
  (215) rows are split by the accounting's own sub-items, not site by site; the accounting's 91
  "not split" adapters are in my 587.
- **Unchecked casts are found by my approximation** of javac's rule (subtype tests in
  `LibGenScan.visitTypeCast`), because `@SuppressWarnings("unchecked")` hides javac's own
  warnings at those 32 places. I read the 32 suppressed places; I did not check each against
  the JLS.
- **Uses of functional values** are recorded for variables and fields (`fnuses.tsv`), and
  flows into `Object` for all expressions; a functional value that is the result of a call and
  is compared or tested at once would be seen by neither. I found none by reading the lists,
  but that is not a scan.
- **Read-only classification** of wildcard declarations is by method name against a list of
  reading methods (`an3.py`), not by an effect analysis, and method results (37) are classified
  only by the for-each loops and flows at their callers.
- **Go performance of generic interfaces inside generic code.** The README's rule says an
  assertion to an interface naming a type parameter is looked up on every call. Converting a
  `*TList[N]` to `List[N]` inside the generic graph classes is a conversion, not an assertion,
  and I did not measure its cost.
- **The handwritten runtime's own callers of generated code** (`asList_`, `rt_proto*.go`) and
  the protobuf generator were sized by line count only.
- **Boxed primitives as type arguments (188 declarations)** are left as `any` in every option;
  whether `List<Integer>` should become `List[int32]` (null elements, `Map.get` absence) was
  not studied.
- The Java prep tree in the worktree is `main`'s; the shared cache's file list was stale
  (prep 19/20's `SimpleCollection` missing) and was regenerated in my copy only.
